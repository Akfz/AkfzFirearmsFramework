AFF - фреймворк для пушек, построен вокруг нативного C++ ядра физики пуль(не работает на MAC, потому что у меня его нету для компиляции)
и гибкой системы конфигов. Проще говоря готов технически, но весь визуал на пользователе.

# Фишки
- **Нативное ядро физики (C++ / JNI)**: Высокопроизводительная симуляция полёта пуль с субшагами, raycast по AABB, гравитацией, сопротивлением воздуха и ветром. Работает в отдельном пуле потоков (`BulletManager`), не нагружая основной тик сервера.
    - **Автоматический фолбэк**: если нативная библиотека недоступна (`NativeBallisticsLoader` не нашёл для текущей платформы), движок прозрачно переключается на чистую и более простую Java-реализацию (`JavaBulletPhysics`) с DDA-raycast.
- **Продвинутая баллистика**:
    - Расчёт энергии удара (`E = ½mv²`), пробития по толщине блока и углу встречи.
    - **Рикошеты** с настраиваемым шансом, зависящим от угла, твёрдости материала и скорости.
    - **Сквозное пробитие** до 16 блоков за один выстрел с сохранением точек попадания.
    - Разделение попаданий по **сущностям** и **блокам** с корректной передачей результата в Java-слой (`HitResult`).
- **Система материалов**: Каждый блок сопоставляется с материалом через `materials.json` (плотность, твёрдость, `maxPenetrationJoules`, флаги `breakAble` / `dropOnBreak`). Работает по `ResourceLocation`, кэшируется по `BlockState`.
- **Динамический ветер и окружение** (`EnvironmentSystem`): Направленный ветер по измерениям (км/ч), raycast на 8 блоков для определения замкнутости пространства, множитель `fluidDragMult` (например, x15 в воде), кэш с TTL 5 секунд на чанк.
- **Многопоточная физика**: `BulletManager` крутит цикл в `ScheduledExecutorService` (25 мс), а расчёт — в `ForkJoinPool`-подобном `physicsExecutor` с фиксированным пулом. Результаты синхронизируются обратно в главный поток сервера.
- **Гибкая система оружия**:
    - Интерфейс `Gun` + дефолтная реализация `DefaultGun` + `InfiniteGun` для креативщиков.
    - **Пять режимов огня**: `SINGLE`, `BURST`, `AUTO`, `BOLT` с корректной обработкой `triggerReleased`, отдачи и задержки между выстрелами.
    - **Три системы питания**: `DirectFeedingSystem` (внутренний магазин + патронник), `MagazineFeedingSystem` (съёмные магазины с NBT-сериализацией), `InfiniteFeedingSystem` (бесконечный боезапас).
    - Сериализация состояния в NBT: тип патрона в патроннике, содержимое магазина, режим огня, `lastShotTime`, `needsChambering`.
- **Настраиваемая система биндов** (`BindManager`):
    - Пять типов: `CLICK`, `RELEASE`, `HOLD`, `DOUBLE_CLICK`, `TOGGLE`.
    - **Группировка по клавише** с разрешением конфликтов (например, R одновременно = перезарядка по отпусканию, разрядка по двойному клику, проверка по удержанию).
    - Поддержка колёсика мыши, настраиваемые окна `doubleClickWindow` и `holdActivationTime`.
    - Сериализация в `binds.json` с автосозданием дефолтов.
- **Событийная модель** (`AsLib.EVENT_BUS`): `BulletSpawnEvent`, `BulletHitEvent`, `RecoilReceiverEvent`, `PressedBindEvent`, `PreLoadRegistryEvent` — всё отменяемое, всё с изменяемым контекстом (`BulletHitContext` даёт доступ к скорости, углу, энергии и позволяет переопределить урон).
- **Сетевой слой**: `BindsSyncPacket` (спам-бинды с серверной валидацией), `SyncRecoil` (отдача на клиент).
- **Реестры**: `AmmoRegistry`, `MagazineRegistry`, `GunRegistry` — регистрация патронов, магазинов и конфигов оружия с защитой от дубликатов.
- **Отладка**: `BulletDebug` рисует партиклами трейл, хитбоксы, вектор скорости и ветра. Флаг `BulletManager.DEBUG` включает подробный лог нативного и Java-ядра с выгрузкой буфера результатов.
